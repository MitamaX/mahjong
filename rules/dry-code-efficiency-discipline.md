# 중복 불허·효율 강박

코드의 효율성을 강박적으로 검토한다. 중복은 용납하지 않는다.

- CSS: 요소마다 새 스타일을 만들지 않는다. 유형별로 공유 가능한 클래스/토큰을 만들어 관리한다.
- JS: 객체지향적으로 구성한다. 같은 로직이 두 번 나타나면 즉시 추출한다.
- 무엇보다 보기 힘든 코드는 절대 허용하지 않는다. 클린 코드 원칙이 최우선. **코드는 아름다워야 한다.**

**Why:** 중복과 난독한 구조는 결함이다. 유지보수와 규격 통일이 모두 여기서 무너진다. 가독성과 미감은 취향이 아니라 요구사항이다.

**How to apply:** 새 스타일을 쓰기 전에 기존 공용 클래스가 있는지 먼저 확인하고, 없으면 재사용 가능한 형태로 만든다. 색·간격·크기는 변수/토큰으로 중앙 관리한다. JS는 책임 단위로 클래스/모듈을 나누고, 반복되는 절차는 메서드나 상위 추상으로 뽑는다. 작성 후 스스로 중복·복잡도를 다시 훑고 정리한 뒤 내놓는다.
